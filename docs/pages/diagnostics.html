日志与诊断

使用软件“查看日志文件”打开日志根目录。日志在与 App 同级的 Logs 中，按日期和分类归档，例如 Logs/20261022/Error/。

分类主要内容
Info初始化、设备连接、启停和换卷等运行阶段。
Records用户操作、通知、生产报警及相关权限信息。
Debug检测、通信、相机启停和性能细节。
Error异常、超时、通信失败和需要关注的技术告警。

日志约 10 MB 后分卷。收集故障资料时直接复制当天整个日期目录，保留带 .1、.2 等序号的文件，同时记录软件版本、故障时间、料号、膜卷和操作过程。

“软件信息 → 导出诊断包”可生成诊断资料；“建议与反馈”可打开反馈入口。参数变更审计与 TXT 运行日志属于不同记录，查看参数历史时使用软件审计入口。

按阶段分析问题

  1. 先明确现象：没有图像、检测结果不对、文件没保存、点位没更新或设备没动作，要分开描述。
  2. 再定位最后完成的阶段：启停搜索 SystemOperation，自动取流搜索 CameraAutoCapture，换卷按同一“换卷#”关联阶段。
  3. 查看相邻错误：找到最后一个开始但未返回的阶段，结合相机、控制器和保存日志分析；界面提示不是唯一证据。
  4. 保留原始信息：保存当天日志、提示原文和相关数据，避免反复重启或覆盖文件导致线索丢失。

初步排查可以缩小问题范围，但连接成功、试检通过或文件存在，都不能单独证明整条现场业务链路正确。

查看参数变更记录

通过顶部“日志”菜单进入参数审计，按时间和相关条件查找变更。先核对变更对象、保存时间和修改内容，再和故障发生时间比较。

审计用于查看变更历史，不会自动恢复旧配置。运行日志用于判断执行阶段，二者应结合查看。输入框改过但未保存，与参数已经写入并生效需要区分。

导出诊断包

通过“帮助 → 软件信息”核对版本，点击“导出诊断包”，在选项窗口选择需要的资料和输出位置，再执行导出。按实际问题选择日志与配置等资料，保留故障时的原始文件。

解压后先查看根目录的“导出说明.txt”。文件名沿用原有时间命名，来源和环境信息记录在说明中：

信息用途
诊断设备标识、计算机名设备标识由有效硬件 UUID 生成，用于辅助核对是否来自同一工控机，与授权机器码无关。读取失败会记录原因，不使用固定兜底码。更换硬件或硬件标识异常时需结合计算机名、MAC 和工位核对。
现场、工位、设备编号及程序信息区分不同工位和软件目录；结合进程 ID、软件启动时间判断是否为同一次运行的前后导出。
本机网卡及通信配置查看系统返回的全部网卡，包括断开、虚拟和回环接口，以及 IP、掩码、网关、DNS、DHCP、MAC、接口类型和链路速度。保存配置摘要列出 PLC、控制器、相机、MES、工位交互和 FTP 等已有地址；网络端点只保留主机和端口，不展开账号、密码和请求参数。
运行状态与系统资源记录导出时的软件运行状态、料号、膜卷号和已有设备状态标志，以及 Windows、CPU、内存和本机固定磁盘容量。设备状态标志为 False 也可能是未启用或未初始化，不能单独判断为断线。

“已保存配置摘要”与“导出时运行状态”分开记录。勾选 Config 时，摘要读取成功收集的配置副本；未勾选时，仍从磁盘 Config 只读提取白名单摘要，不打包完整配置。缺少字段不推断默认值；保存值不代表当前连接实际采用的地址，需重启生效的参数尤其要核对。环境信息按各自时间采集，不还原故障时状态，也不主动测试设备连通性。

部分环境信息读取失败时会注明缺项并继续收集其他资料。摘要对网络端点的处理不改变完整 Config 和日志原文的收集规则。

提交问题时补充发生时间、当时操作、当前料号和膜卷号、涉及相机或设备，以及能否稳定重现。提示窗口应保留完整原文，不只记录“失败”。

常见现象从哪里查

现象优先检查
没有图像相机连接、启用状态、触发方式、编码器信号和采集日志；参见相机与采集。
尺寸偏差或抓不到边原图、标定、区域、方向、极性、阈值与补偿；参见直线与尺寸。
瑕疵少检、误检或类别不对检测区域、模板、模型、面积过滤及二次分类；参见分类与过滤。
报警后 PLC 没动作触发条件、事件开关、连接、地址、类型与写入结果；参见报警设置。
纠偏没有输出设备连接、启用、有效样本、死区、输出限制及实际发送记录；参见闭环纠偏。
查不到数据或文件保存开关、筛选、数据库、路径、卷号、空间与清理记录；参见数据保存与查询。

通用说明不能替代项目专用协议或外部设备确认。先收集可以对应同一时刻和同一对象的证据，再判断问题在哪个阶段。

一次问题记录包含什么

  • 时间：精确到分钟或秒，注明第一次发生与最近一次发生。
  • 对象：软件版本、当前料号、膜卷、相机、面别和相关设备。
  • 操作：发生前做了什么；停止再启动、更换图像或切换料号后是否仍发生。
  • 原始资料：完整提示、故障当天日志、原始图像或对应结果文件；参数问题同时保留相关配置。
  • 已经确认的事实：例如有回调图但没有检测结果、写入返回失败、某卷报表缺失，分别记录。

用同一时间和同一对象关联资料。只说“没有反应”难以区分未触发、正在等待、已失败还是外部设备没有动作；可从通信检查顺序或开检提示进入。
