常见现象从哪里查

现象 优先检查
没有图像 相机连接、启用状态、触发方式、编码器信号和采集日志；参见相机与采集。
尺寸偏差或抓不到边 原图、标定、区域、方向、极性、阈值与补偿；参见直线与尺寸。
瑕疵少检、误检或类别不对 检测区域、模板、模型、面积过滤及二次分类；参见分类与过滤。
报警后 PLC 没动作 触发条件、事件开关、连接、地址、类型与写入结果；参见报警设置。
纠偏没有输出 设备连接、启用、有效样本、死区、输出限制及实际发送记录；参见闭环纠偏。
查不到数据或文件 保存开关、筛选、数据库、路径、膜卷号、空间与清理记录；参见数据保存与查询。

通用说明不能替代项目专用协议或外部设备确认。先收集可以对应同一时刻和同一对象的证据，再判断问题在哪个阶段。

日志与诊断

使用软件“查看日志文件”打开日志根目录。日志在与 App 同级的 Logs 中，按日期和分类归档，例如 Logs/20261022/Error/。

分类 主要内容
Info 初始化、设备连接、启停和换卷等运行阶段。
Records 用户操作、通知、生产报警及相关权限信息。
Debug 检测、通信、相机启停和性能细节。
Error 异常、超时、通信失败和需要关注的技术告警。

日志约 10 MB 后分卷。收集故障资料时直接复制当天整个日期目录，保留带 .1、.2 等序号的文件，同时记录软件版本、故障时间、料号、膜卷和操作过程。

“软件信息 → 导出诊断包”可生成诊断资料；“建议与反馈”可打开反馈入口。参数变更审计与 TXT 运行日志属于不同记录，查看参数历史时使用软件审计入口。

查看参数变更记录

通过顶部“日志”菜单进入参数审计，按时间和相关条件查找变更。先核对变更对象、保存时间和修改内容，再和故障发生时间比较。

审计用于查看变更历史，不会自动恢复旧配置。运行日志用于判断执行阶段，二者应结合查看。输入框改过但未保存，与参数已经写入并生效需要区分。

出现“写入审计日志失败”时，核对测量数据库目录下 SystemLogs/AuditLog.db 的目录、写入权限和磁盘状态；TXT 运行日志与审计库是独立记录。配置可能已经保存成功，应分别确认保存结果和审计结果，不要删除数据库或清空原配置。

导出诊断包

通过“帮助 → 软件信息”核对版本，点击“导出诊断包”，启动独立诊断工具。启动成功后软件信息窗口自动关闭，主软件继续运行。填写故障信息，在“高级设置”核对资料范围、日志日期和输出位置，再点击“导出”；具体步骤见填写信息并导出。

若提示“未找到诊断工具”及实际路径，检查 App\Bin\UtilityTools\DiagnosticExport\导出诊断包.exe 是否存在；其他启动异常按完整提示检查文件权限和路径，并在 Error 日志中查找“启动诊断工具失败”。启动失败时软件信息窗口保持打开。工具版本 v1.0.3 会将已存在的额外日志目录按来源编号写入包内，并在“导出说明.txt”记录来源。

解压后先查看根目录的“导出说明.txt”。说明开头记录填写的现场故障信息，后续记录来源、环境及缺项：

信息 用途
诊断设备标识、计算机名 设备标识由有效硬件 UUID 生成，用于辅助核对是否来自同一工控机，与授权机器码无关。读取失败会记录原因，不使用固定兜底码。更换硬件或硬件标识异常时需结合计算机名、MAC 和工位核对。
现场、工位、设备编号及程序信息 区分不同工位和软件目录；结合进程 ID、软件启动时间判断是否为同一次运行的前后导出。
本机网卡及通信配置 查看系统返回的全部网卡，包括断开、虚拟和回环接口，以及 IP、掩码、网关、DNS、DHCP、MAC、接口类型和链路速度。保存配置摘要列出 PLC、控制器、相机、MES、工位交互和 FTP 等已有地址；网络端点只保留主机和端口，不展开账号、密码和请求参数。
系统资源与进程信息 记录 Windows、CPU、内存和本机固定磁盘容量，主程序进程信息按实际读取结果记录。不采集主程序内存中的料号、膜卷号或设备业务状态。

工具只收集磁盘上已保存的资料，不能刷新主程序尚未落盘的日志。勾选 Config 时，摘要读取成功收集的配置副本；未勾选时，仍从磁盘 Config 只读提取白名单摘要，不打包完整配置。缺少字段不推断默认值；保存值不代表当前连接实际采用的地址，需重启生效的参数尤其要核对。环境信息按各自时间采集，不还原故障时状态，也不主动测试设备连通性。

部分环境信息读取失败时会注明缺项并继续收集其他资料。摘要对网络端点的处理不改变完整 Config 和日志原文的收集规则。

提交问题时补充发生时间、当时操作、当前料号和膜卷号、涉及相机或设备，以及能否稳定重现。提示窗口应保留完整原文，不只记录“失败”。

软件打不开时导出诊断包

软件无法启动时，可使用 导出诊断包.exe 收集已保存资料。工具位置、故障信息填写、截图附件及导出步骤见独立诊断工具与故障资料。

按阶段分析问题

启动慢时，在 Info 中搜索“启动步骤开始”“启动步骤完成”和“启动里程碑”，按模块比较开始、耗时与累计时间；并行模块的耗时不能直接相加。分别核对“后台初始化开始”“检测初始化就绪”“后台初始化结束”“主界面布局与首帧等待结束”和“主界面首次可见”。初始化期间只显示进度窗，首帧等待超过 2 秒会记录异常并继续交接。初始化就绪仍需通过原有权限、相机、标定、配置及模型校验。

进度摘要会移除已完成的模块，最多显示两个简短模块名和待完成数量，完整名称在步骤日志中查看。百分比按阶段推进，单个模块加载超过 3 秒且没有其他待完成项时显示该模块用时。看到等待 PLC 或相机时，先核对对应步骤的结束日志，不把等待时间归到前一个已经完成的模块。MES 分别记录配置读取、应用和连接耗时；未启用的喷码会记录跳过原因。设备普通连接失败和连接超时只显示红色状态，详细原因仍写入日志；读取、加载失败及程序异常才进入启动汇总提示。

初始化结束后仍需等待较长时间时，在 Info 中搜索“启动界面阶段”，分别查看主窗口控件创建、首次主题、首次同步布局、首次布局调度与控件加载、首帧信号等待等耗时。主题未变化时会记录跳过重复应用。界面日志用于定位交接耗时，不表示实际相机已出图。

侧边栏、主页页签或其他页面页签切换较慢时，在 Debug 和 Info 中搜索“界面性能”，按同一 Op 编号查看开始、阶段耗时及总耗时。侧栏区分点击反馈、导航检查、目标页初始化及布局调度；导航检查可能包含用户确认、登录或保存等待，不能把整段时间都视为界面计算耗时。“离线仿真清理”可区分相机停止等待和图像释放，“历史查询”区分数据库查询与表格绑定。

普通切换记录在 Debug，达到 200 毫秒的阶段及慢刷新记录在 Info。统计表、直方图、分布图、虚拟图和尺寸过程显示可按模块名称查找慢刷新。“UI调度延迟”表示一次低优先级界面任务等待至少 500 毫秒；长时间未响应时可看到“UI等待中”。这类记录反映 UI 线程繁忙或排队，不等同于软件崩溃，也不是屏幕首帧时间。后台异步查询可能在页签布局完成后继续，须结合对应查询日志判断。

启动步骤异常或超时在 Error 中记录模块、耗时和详细异常，设备日志同时包含相机、地址、SDK 阶段等信息。常规本地配置、数据库、缓存及单路 PLC、控制器初始化默认等待 10 秒，单台相机和单个 AI 模型默认等待 60 秒；已有更短驱动超时继续生效。超时表示本轮结果未被采用，不能据此认定原生 SDK 已停止执行。

  1. 先明确现象：没有图像、检测结果不对、文件没保存、点位没更新或设备没动作，要分开描述。
  2. 再定位最后完成的阶段：启停搜索 SystemOperation，自动取流搜索 CameraAutoCapture，换卷按同一“换卷#”关联阶段。
  3. 查看相邻错误：找到最后一个开始但未返回的阶段，结合相机、控制器和保存日志分析；界面提示不是唯一证据。
  4. 保留原始信息：保存当天日志、提示原文和相关数据，避免反复重启或覆盖文件导致线索丢失。

初步排查可以缩小问题范围，但连接成功、试检通过或文件存在，都不能单独证明整条现场业务链路正确。

一次问题记录包含什么

  • 时间：精确到分钟或秒，注明第一次发生与最近一次发生。
  • 对象：软件版本、当前料号、膜卷、相机、面别和相关设备。
  • 操作：发生前做了什么；停止再启动、更换图像或切换料号后是否仍发生。
  • 原始资料：完整提示、故障当天日志、原始图像或对应结果文件；参数问题同时保留相关配置。
  • 已经确认的事实：例如有回调图但没有检测结果、写入返回失败、某卷报表缺失，分别记录。

用同一时间和同一对象关联资料。只说“没有反应”难以区分未触发、正在等待、已失败还是外部设备没有动作；可从通信检查顺序或开检提示进入。
