管理相机配置

进入相机配置，选择相机后使用添加、修改或删除按钮，完成后点击“保存相机配置”。先核对驱动类型和设备连接参数，再保存。此入口与料号参数保存不同。

相机配置决定本次启动使用的设备、连接参数和测量数据集。新增或修改后须保存并按提示重启；运行中的连接与释放使用“相机连接管理”。两者用途不同。

新增或修改相机

  1. 停止检测，在“系统设置 → 相机管理 → 相机配置”选择添加或修改相机。
  2. 核对软件显示名称、驱动类型、面别、显示顺序和设备选择字段。
  3. 按当前驱动提示填写名称、IP、设备索引或采集资源；使用厂商工具核实真实值。
  4. 点击“保存相机配置”，按提示重启软件。
  5. 重启后检查加载提示，再在参数页选择相机获取图像，确认方向、幅面、曝光与触发条件。

更换相机、分辨率或安装位置后，继续检查标定标零、定位区域和注册模板。软件显示名称与物理设备名称的用途因驱动不同，不能随意互换。

相机连接管理

启动连接按相机顺序进行，每台默认最多等待 60 秒，并与其他设备及 AI 加载并行。普通连接失败会继续下一台；若 SDK 超时仍未返回，后续相机标为“前一台 SDK 操作未结束，未尝试连接”，软件继续进入主界面。此时不要在其他工具中同时操作同一设备；先保留日志，等待原操作返回后再检查或重启软件。超时后晚到的成功结果不会恢复连接状态。

从任意页面顶部“工具 → 相机连接管理”打开窗口，使用具备“系统设置”权限的账号操作。运行中也可打开查看状态，连接或断开前须停止检测。窗口列出本次启动配置的全部相机，包括启动连接失败的相机；例如配置 10 台而 2 台连接失败时，仍显示完整 10 台，异常相机状态为红色，并显示失败原因。

  1. 找到相机，点击“断开连接”，等待释放完成；底栏对应相机显示异常状态。
  2. 使用厂家工具连接、调试相机，结束后先在厂家工具中释放连接。
  3. 回到本软件点击“连接”。连接成功后相机保持停止状态，底栏恢复正常；全部相机连接成功后才能启动检测。

正在检测时不能连接或释放相机，自动停流仍属于检测运行中。初始化、权限或运行状态不允许操作时，具体原因在管理窗口内显示。启停、采集、连接和退出操作未结束时，应等待完成再操作。连接和断开期间显示进度条及等待秒数，禁止重复操作和关闭窗口；驱动响应较慢时会提示继续等待，不表示操作已经失败。释放失败时保留原实例，按窗口原因检查并重试“断开连接”，释放成功前不能直接重新连接。

手动和自动启动都会检查全部相机。未配置相机、任一相机未连接、连接异常或正在操作时均禁止启动；关闭普通配置检查也不能跳过此要求。连接管理使用本次启动的配置，相机配置的新增、修改和删除仍需保存并重启软件生效。

连接与取图

在添加或修改相机窗口的“文件与存图”区，“图像格式”右侧可勾选“分时/多重曝光（明场上、暗场下）”。窗口内容显示不全时可向下滚动，确认、取消按钮保持在底部。

“分时/多重曝光”是每台相机独立的图像业务设置，与 Mono8P2 等像素格式分别保存。启用时，明场固定在图像上半部，暗场固定在下半部；按实际图像分别添加检测区域。请按实际采集方式确认勾选状态并保存。

检测使用当前帧实际宽高，各相机可分别输出 16K 或 8K 横向图像；相机配置宽高用于设备连接及离线图像核对。配置了有效宽高时，加载不一致的离线图像会提示并停止加载，不会自动缩放来匹配相机。

测量数据集尚未配置时，相机表格显示“未配置，请设置”；详细相机名称写入 Error 日志，启动时不弹窗。请配置正确的数据集、保存并重启软件。

不同相机按 IP、名称或索引连接，所需字段和配置文件各不相同。按相机类型与连接参数选择驱动，逐项填写实际使用的字段。

进入尺寸或瑕疵设置时，先选择当前相机，再获取或加载图像。没有有效图像时先解决采集或图片加载问题，不用其他相机的图像代替当前相机。

尺寸、瑕疵、料号引导和点检等页面获取实时图像前，会检查本次启动配置的全部相机。任一相机未连接、连接失败或连接异常时，禁止获取并提示未就绪相机及原因；先在相机连接管理中处理后重试。本地加载图片不受此连接检查限制。

本地相机仿真

本地相机按文件名排序读取配置目录中的 BMP、JPG、JPEG、PNG 图片，转换为灰度后循环出图。每台相机独立缓存最多约 5 GiB（5 × 1024³ 字节），以解码后的宽 × 高估算占用。

坏图或超过剩余预算的图片会记录原因并跳过，继续尝试后续文件；内存不足时结束本轮加载，保留已经加载的图片。至少成功加载一张才视为连接成功。日志记录加载张数和估算缓存字节数。该额度只限制常驻灰度图缓存，解码及检测还需要额外内存，多台相机的额度分别计算。

跟随运动自动取流

部分项目提供“相机自动取流”，可按速度、米数或脉冲判断运动。保存策略后，下次成功启动检测时生效；目前该功能用于正运动系统控制器。

持续静止后软件自动停流，有效运动恢复后重新启流。自动停流期间检测仍可显示运行中。读取无效时保持当前取流状态；自动动作失败会暂停本轮控制，处理提示后停止并重新启动检测。

采集状态怎样区分

“设备持续无有效运动，相机已自动停止取流，检测仍在运行。”是自动策略提示，不等同于手动停止检测。恢复运动后仍未出图时，再检查控制器数据与逐相机动作结果。提示自动动作失败并暂停时，保留逐相机结果，处理原因，再手动停止并重新启动检测。

现象 检查方向
初始化失败 驱动运行库、设备名称、IP、板卡或资源索引、设备占用，以及原始错误码。
已连接但不出图 是否启流、触发源、设备是否运动、门控、曝光与光源。
出图但黑屏或花图 像素格式、图像大小、曝光、照明、接线和厂商工具中的图像。

逐相机检查，避免因另一台相机正常就判断全部采集已就绪。普通连接失败或连接超时只显示红色状态并记录日志；插件、图像文件加载失败及程序异常会汇总提示，后续问题查看当天错误日志。

没有图像或图像顺序异常

  1. 记录相机名称、驱动、异常时间及设备是否正在运动。
  2. 检查连接状态、触发信号、光源和自动取流状态，区分“未连接”“已连接但未取流”“有帧但图像不正确”。
  3. 查看当天 Error 中的相机、SDK、阶段和错误码；初始化失败时保留“相机初始化异常”提示。
  4. 自动启停问题搜索 CameraAutoCapture，按轮次和操作编号关联开始、逐相机返回和完成日志。

初始化异常不一定表示相机被占用。DALSA GigE 提示“未枚举到 AcqDevice 相机资源”时，先检查供电、网线、网卡和 Sapera 驱动；提示设备名称未匹配时，对照提示中的已发现资源核对名称。提示打开相机失败时，再结合原始错误检查配置文件、连接及其他程序占用；厂商工具使用完相机后应先释放连接。缓冲创建失败则检查可用内存、图像尺寸与像素格式。按索引连接的驱动须核对实际枚举数量，索引从 0 开始。

采集卡返回成功不一定包含相机控制命令的结果。需要同时检查相机命令和触发门控记录，而不能仅凭一条“启流完成”判断所有环节正常。

日志与异常检查

普通连接失败先看管理窗口中的相机名称、状态和原因，再查当天 Error 中的相机、SDK 阶段与错误码。自动启停搜索 CameraAutoCapture；界面加载与相机真实出图应分开判断。
