PLC 与系统控制器

先区分系统控制器与独立设备 PLC，再检查对应连接、型号、地址和数据类型。软件的尺寸结果、报警、纠偏、清米等输出各有条件，不能只凭“PLC 已连接”认定全部点位都在写入。

“系统设置 → 系统控制器 → 控制器连接”的启用状态保存后需重启生效。未启用时跳过该控制器连接、心跳、周期读取以及对应清米、编码器和采集门控，相关读写测试不可用；独立主 PLC 的原有业务不受此开关代替。

“调用结束”“写入已调度”“写入成功”和“设备实际动作完成”不是同一结果。排查时应逐层核对软件返回、PLC 点位和设备动作。

主设备 PLC 点位

在数据交互的主设备点位页，按生产信息读取、实时数据与控制输入、心跳与通信、软件与检测状态、闭环及专用业务信号分类设置；每项旁边说明读写方向、触发时机和格式。尺寸和瑕疵事件报警在“报警设置”中独立配置。

测量值与分类瑕疵分别在“尺寸交互PLC”和“瑕疵交互PLC”页签维护独立配置。控制器断连状态量继续同步“故障 1、正常 0”，与详细报警的断连事件地址独立，不使用报警保持时间。数据更新完成和点检超时停机等业务点位继续保留。

规格牌和详细报警的事件输出支持“地址|bool”“地址|int”“地址|float”，省略类型按 float 写入；人工复位命令在详细报警公共设置中单独选择类型。保持和复位行为参见PLC 报警保持时间。

无锡松下刻码

无锡松下现场使用专用刻码信号。启用双面检测并配置 AB 面相差笔数后，软件按相差方向配对两面的瑕疵和刻码尺寸：正数表示 A 面先到，负数表示 B 面先到。前面的未配对笔数会等待对应另一面到齐，配对完成后只发送一条刻码信息。

多同步组场景会等待完整批次再发送，避免同一物料由局部结果重复触发。刻码内容写入成功后才输出检测 NG 信号；检查时应同时核对刻码内容地址、检测功能地址、数据交互开关和 PLC 通信状态。

修改料号、换卷、停止检测或调整 AB 相差笔数后，应重新确认配对状态从新批次开始。出现等待超时、帧序列中断或 PLC 写入失败时，结合通信日志检查当前批次是否被丢弃以及地址配置是否正确。

MES 通信

通用 MES 使用一份主配置，支持 TCP、HTTP、MQTT，分别配置尺寸过程上传和瑕疵过程上传。尺寸包含现有尺寸与错位数据。料号切换不再选择其它 MES 配置；冠宇认证、换型和生产开停、达力卷号和文件通知等专用业务继续使用对应项目流程。

  1. 打开“MES 配置”，核对“启用 MES”、协议和连接参数。HTTP 在选中接口后填写对应的完整 URL；TCP、MQTT 填写主机名或 IP 和 1～65535 的端口。
  2. 选择“尺寸过程上传”或“瑕疵过程上传”，勾选对应的“启用尺寸上传”或“启用瑕疵上传”，独立选择模板或固定格式。两种模式分别保留编辑内容。
  3. 配置参数来源，点击右侧“检查配置”，再用“测试发送”检查返回结果。运行中可以编辑、检查和测试；停止检测且待上传任务处理结束后，点击“保存并应用”。保存继续按现有权限确认。

应用成功后更新生产连接。保存成功不代表服务器可达；断连时检查目标及返回原因。MES 总开关与主配置开关同步；启动时发现不一致，按关闭优先处理并记录日志。

协议设置与核对
HTTP填写 http:// 或 https:// 开头的完整地址。正文方式包括“JSON（UTF-8 无 BOM）”“表单字段”和“JSON（UTF-8 带 BOM）”，新配置默认无 BOM。表单方式需填写承载正文的字段名；带 BOM 方式的正文开头包含 UTF-8 字节序标记，按接收方要求选择。HTTP 不要求 Ping 成功，以实际请求结果判断。
TCP普通正文用 UTF-8；“专用报文封装”用 GB2312，格式为 STX + 消息序号 + TAB + 设备名称 + TAB + 命令标识 + TAB + 正文 + ETX。STX 为 0x02，TAB 为 0x09，ETX 为 0x03；勾选封装后才显示设备名称及当前接口的命令，尺寸与瑕疵命令分别设置。
MQTT填写客户端标识、认证信息和发布主题；发布主题不能含 + 或 # 通配符。仅发布上传报文，不配置订阅。旧配置需要的网关连接通知按原行为保留。

MES 模板与固定格式

模板模式从左到右为变量绑定、报文模板和发送测试，区域间距固定。左侧绑定表纵向滚动，选中行后在下方设置来源；测量来源显示当前料号的真实尺寸、错位名称，可指定中文数据集；选择“固定值”时填写固定内容。固定格式的选中项设置位于字段表右侧，字段名可编辑。连接设置中的 TCP 封装、MQTT 等参数使用右侧空间排列，窗口较窄时自动换行。

点击“添加”生成“变量1、变量2……”等固定标识，选择来源后点击该行的“复制”，再在模板需要的位置粘贴蓝色的 #变量1#。复制只写入剪贴板，不改动正文或光标，也不会拆开已有变量；粘贴位置由操作者确定，可用撤销恢复。已有配置的自定义变量名称保留，模板绑定标识只读，避免改名后与正文脱节。也可直接在正文输入占位符，软件自动列出待绑定项。“正文”列显示出现次数、未绑定或未插入；未插入的配置行不会参与发送。同一变量可重复出现并使用同一测试值，但不能配置冲突的同名绑定。

模板不选择数据类型，只把占位符替换为参数原文，不限制 JSON、XML 或其它报文格式，也不自动加引号或转义。例如 卷号=#roll#;速度=#speed# 可直接使用。引号、分隔符、换行及业务结构由模板自行控制，替换值中的占位符不会再次展开。

固定格式可配置普通字段、嵌套数组和嵌套 JSON，选中嵌套字段后编辑下方子字段。普通字段与子字段只选择“字符型”或“数值型”：字符型自动加双引号并转义，数值型必须是有效数字且不加双引号。键值数组沿用 Param_Code、Param_Value 格式。嵌套 JSON 的父字段选择字符型时，整个对象作为 JSON 字符串输出；其它方式按嵌套结构生成对象。

“固定值”来源允许合法的空字符串。其它来源取不到必需参数、变量未绑定或固定格式的数值无效时，阻止当前报文，记录接口、参数及原因，继续后续条目；不会自动以空串或零代替，也不自动补传。模板原文中的空格保持不变。“检查配置”统一检查连接参数、绑定、测试值和替换后报文；当前接口尚未启用时也执行检查，并提示生产上传未启用。JSON 语法问题单独列为格式提示，不限制普通文本或 XML 模板发送。检查不会发送请求。

时间来源含义与单位
本地时间（yyyy-MM-dd HH:mm:ss）进入 MES 处理时的本地时间，例如 2026-11-03 09:18:00。
UTC 时间（yyyy-MM-ddTHH:mm:ssZ）对应的 UTC 时间，例如 2026-11-03T01:18:00Z。
Unix 时间戳（秒）／Unix 时间戳（毫秒）自 Unix 起点的秒数／毫秒数，作为 JSON 数字使用时不加双引号。

同一份报文重复使用时间变量时取值一致，不要求先打开页面或连接成功。已有检测值取本笔结果；设备编号、料号、卷号、当前速度、当前米数和当前账户在入队时固定。当前时间表示 MES 处理上下文时间，不能当作相机采集时间。账户来源不包含密码。共享文件字段及既有 PLC 地址占位语法继续按现场配置使用，不会因此增加 PLC 读取。

MES 上传频率与瑕疵范围

尺寸接口显示“每 X 笔发送 1 次”，每笔按全部同步组到齐后的完整批次累计，不是时间间隔，X 至少为 1。瑕疵接口只显示“仅发送首个瑕疵”，无瑕疵时不发送瑕疵明细；未勾选时，每个瑕疵分别生成一份报文；勾选后只上传该笔现有列表中的第一个，不排序、不跨笔合并。

首个选项只影响明细上传，不减少参与检测与计数的瑕疵。新配置默认全部上传；旧配置首次加载时推导并显示原有首个或全部规则，保存后明确记录。本次不提供换卷统计上传接口；共享文件结束状态和旧卷排队数据失效规则继续生效。

MES 测试与配置文件

  1. 进入页面或切换接口后自动填充测试数据，无需先点击模拟：按当前料号模拟一笔尺寸、错位和瑕疵；时间、设备编号、卷号、速度、米数、账户等使用当前真实快照。测试行按模板中变量首次出现的顺序排列，包括固定值；重复变量只显示一行，不同变量即使来源相同也可分别修改。点击测试值即可连续输入，无需双击进入单元格编辑。悬浮查看来源，“状态”列标出自动、固定值、手动或缺项。未绑定项需先设置来源；有来源但未取到值时可手动补充。测试值填充后保持固定，更换某项绑定后该项重新填充，其余手动值保留。
  2. 点击“测试发送”，自动填充参数、生成报文，使用独立连接向当前目标发送，MQTT 测试使用临时客户端标识以避免挤掉生产连接；无需先生成预览；结果显示目标、耗时、返回或失败原因。测试会产生真实请求，使用前核对目标服务器及主题。

TCP 写入完成、MQTT 发布完成、HTTP 成功状态和 MES 业务接受是不同结果；通用 TCP 未定义业务应答时只能确认已写入连接。HTTP 显示实际状态码和返回正文，带 BOM 方式也会保留错误返回；返回正文仍需按接收方约定核对。独立测试成功不能代替生产通道验证。

“导入配置”只加载编辑副本，显示兼容转换与校验提示，保存前不改变生产配置。“导出配置”校验并导出当前编辑内容，不应用配置，不能直接覆盖生产主文件。唯一通用主文件仍为 MesConfig.xml；读取不会改写原文件，保存失败保留原文件，成功替换时保留 .bak 备份。

旧 Http_Json 转为 HTTP JSON 正文方式；旧主机和接口路径转换为完整 URL，完整 URL 不重复拼接。已删除的通用接口提示后不执行；UDP、PLC 直传及未识别协议会报错，不自动转成 TCP。导入或迁移失败时保留原文件和当前有效配置，修正错误后再导入。

珠海冠宇 mom

现场名称为 zhgy6c 或 zhgy8c 时，均使用“MES 配置”中的“珠海冠宇 mom”页面，读取同一套已有 MOM 配置，维护启用状态、厂部、数据类型、上传频率（完整批次数）、超时秒数和七项接口的完整地址。设备编号自动读取主程序已有的本机配置，在此只读显示，每台电脑使用自己的编号。厂部默认“6部”，可以按现场 MOM 要求修改；已有非空厂部配置继续保留。仅上传本机启用的尺寸、错位数据。修改配置前先停止检测，保存后重新刷卡验证；各接口地址需与现场 MOM 服务一致。

页面上方为七项接口表格及运行参数，设备编号、厂部、数据类型、上传频率和超时使用紧凑输入框，空间不足时自动换行。下方左侧集中显示服务器连接、接口测试和执行结果，右侧对照显示请求与返回报文；宽屏下两份报文并排显示，普通窗口上下显示。服务器 IP、端口与连接测试按钮同行，测试卡号与刷卡验证按钮同行。点击接口行可切换查看该项结果；窄窗口下诊断区域上下排列。七项接口分别勾选启用，修改后点击“保存配置”生效；旧配置未包含接口开关时沿用全部启用。关闭某项后跳过对应调用：人员资质校验关闭时仍按本地卡号查找用户及角色；参数请求关闭时保留当前料号；生产开始、结束关闭时跳过相应 MOM 通知；上传和人员操作日志关闭时停止对应发送。接口仍启用时，MOM 拒绝或网络失败继续按原规则处理。

上游接口关闭导致缺少 MOM 员工工号、工单、产品或批次时，不编造字段；跳过无法组包的下游接口并显示缺项，继续本地检测。本地账号或角色不存在仍不能刷卡登录，停用接口不能代替用户数据恢复。

zhgy6c 的服务器 IP、端口从已保存且启用的接口完整地址读取，只读显示；修改接口地址后需保存。软件启动、启用 MOM 或保存配置后立即检查，之后每 10 秒自动复查；每个目标最长检测 3 秒，不阻塞界面。同一主机、同一端口只检查一次，多个目标并行检测，全部可达才表示正常。点击“测试连接”立即执行同一检查，与当前选中接口无关；页面列出各目标结果和最近完成时间。检测只建立 TCP 连接，不发送 HTTP、人员校验或生产报文，也不恢复上次生产会话；重启或保存配置后仍需正式刷卡再开始生产。未写端口的 HTTP 地址使用 80，HTTPS 使用 443。

zhgy8c 的“测试连接”继续使用页面可编辑的 IP、端口，仅作为独立 TCP 工具，不改写接口地址、不保存测试地址、不改变底灯。两种现场均需分别查看网络、HTTP 和业务结果；端口可达不代表接口路径、人员资质、工单或上传成功。

填写测试卡号后可执行“刷卡验证测试”：先检查本地用户及角色，再请求 MOM；只显示验证结果，不建立登录会话、不缓存生产员工身份，正式生产前仍需在主界面刷卡。“参数查询预览”只显示返回公差，不覆盖料号、不执行换型或办理生产开始。测试和保存均使用现有权限确认；刷卡及参数测试读取已保存接口配置，六厂服务器 TCP 检测读取已保存且启用的接口地址，八厂读取页面 IP、端口。其它接口通过正常启停、实测上传和操作日志流程验证，不提供手动办理批次或上传测试数据的按钮。

“执行结果”区的“查看运行日志”打开现有软件日志目录，可按日期查看：Debug 保存实际 MOM 请求和返回，Error 保存异常、超时及技术告警，Records 保存刷卡认证和人员操作。页面的执行结果是当前接口最近一次记录，不能代替历史日志；六厂 TCP 检测结果同时更新页面和底灯，八厂独立 TCP 测试结果仅显示在页面。

zhgy6c 底灯绿灯明确表示“MOM服务器端口可达”，仅在全部启用目标均可达时点亮；任一目标失败显示红色“MOM服务器端口不可达”，地址或配置异常显示红色“MOM服务器配置异常”。首次检测短暂显示灰色“MOM服务器检查中”，没有启用接口时显示灰色“MOM接口未启用”；周期复查期间保留上次结果，避免闪灯。网络恢复后自动更新，后台检测失败不反复弹窗。HTTP 错误、MOM 业务拒绝及本地参数校验失败仍查看对应接口；服务器端口状态独立于业务通信记录及 PLC 蓝灯控制。

zhgy8c 底部“MOM未验证”仍以灰色表示尚无 HTTP 通信结果；收到 HTTP 响应后“MOM通信”显示绿色，请求网络失败显示红色。HTTP 错误码或业务拒绝不等于端口断开，仍需查看分阶段结果。

zhgy6c 手动开始或结束遇到 MOM 错误时，提示框显示原因、现场处理步骤及当前检测状态。开始检查失败时检测未启动；结束检查失败时检测继续运行。参数公差异常按编码汇总名称、标准值、上下限及单位，需联系 MOM／工艺负责人核对数据和本机测量项编码，修正后在“参数查询预览”复核，再重新开始检测。标准值必须为有效数值且在上下限范围内，不提供忽略校验入口。人员权限异常应核对员工状态与设备授权；缺工号需正式刷卡，缺工单或批次需核对参数接口启用状态及返回字段；网络错误先测试端口，再查看 HTTP 和业务返回。

人员资质校验启用时，刷卡时先按卡号查找本地用户及角色，再将卡号和设备编号直接发送到 MOM。只有 MOM 返回成功才完成登录，权限继续使用该用户已有的本地角色。卡号不存在、MOM 拒绝或请求超时均不允许本次刷卡登录；原有密码登录和启动自动登录方式保留。生产接口需要 MOM 返回的员工工号，未取得时按提示先刷卡验证。

  1. 启用 MES 后，手动点击“开始”会依次执行已启用接口：获取产品参数、直接保存到当前料号、查询 MOM 换型完成状态、请求生产开始，全部成功后启动检测。
  2. 下发参数按宽度及错位的 NG 编码匹配本机启用项，直接覆盖标准值和上下限，无需人工确认。未匹配项及其它参数保留；匹配编码冲突、公差无效或保存失败会提示原因并阻止启动。已成功保存的参数在后续换型或生产校验失败时仍保留。
  3. 过程参数按现有 MES 笔数频率上传，报文保留本次生产的工单、批次和生产开始时取得的 MOM 员工工号；界面自动注销不改变已开始生产的数据归属。判定 WARN 按 OK 上传；上传失败记录原始请求、返回和原因，继续处理后续数据，不自动补传。
  4. 生产结束接口启用时，手动点击“停止”先请求 MOM 生产结束，成功后停止检测；MOM 返回 NG 或请求超时时保持检测运行并显示原因。MOM 的生产结束代表批次完工，暂停检测前应确认该批次可以结束。

人员操作日志按操作发生时的身份上传，操作时间使用 UTC。排查时区分刷卡、参数请求、换型校验、生产开始、过程参数上传、生产结束和操作日志七项业务，保存各自的请求时间、完整地址和原始返回。MOM 返回的 Result 决定业务成功与否，HTTP 连接成功不能代替业务确认。

自动启动及自动／故障停止继续执行原有控制流程；上述 MOM 生产开始、结束校验对应手动启停。现场联调还需核对换型及批次状态、实际参数编码、工单和员工工号。

尺寸交互PLC

进入“数据交互 → PLC数据交互 → 尺寸交互PLC”，配置本机检测或工位交互接收的实时测量值。尺寸、错位按数据集和名称匹配，不随料号切换重新套用旧地址。

  1. 点击“新增尺寸”，选择适用的数据集，再点击名称单元格，从预设尺寸和错位名称下拉框中选择；可用键盘按名称前缀定位。
  2. 填写测量值 PLC 地址，勾选“启用”后点击页面底部“保存”。名称忽略大小写及首尾空白；缺少匹配数据时跳过，不写默认 0。
  3. PLC 连接正常时，后台周期读取最新值。通信忙碌时合并刷新请求，不补发历史尺寸批次。

地址支持“地址|float”或“地址|int”；不写类型时按 float 发送测量值。int 将测量值乘以 100 后四舍五入，接收端需按比例还原。此页不输出标准值、上下限、补偿值、状态、均值或方差。

瑕疵交互PLC

在同一功能下打开“瑕疵交互PLC”，点击“新增瑕疵”，再点击名称单元格，从当前料号瑕疵检测名称下拉框中选择；可用键盘按名称前缀定位。填写 PLC 地址并勾选启用后保存。已有配置中的名称仍保留在下拉候选中，便于查看和维护。名称与检测结果最终显示名称匹配；规则分类和 AI 分类同名时使用同一项配置。瑕疵检测页面只维护检测参数，发送地址在此页维护。

出现匹配瑕疵后，后台向对应地址发送 1。不写类型或使用“地址|bool”时写入 true；“地址|int”写整数 1，“地址|float”写浮点数 1。软件不负责将此类点位清零，不提供确认握手或历史补发。

重复通知可能合并，PLC 繁忙时允许丢弃部分待发送通知；断连期间不保留历史通知，单次失败记录日志后继续。此功能用于瑕疵出现提示，不作为逐个瑕疵的可靠计数。保存配置、切换料号及关闭软件时清除等待请求；已进入驱动的写入可能在其超时前结束。

旧输出配置迁移与保存

升级后首次启动自动逐条迁移全部料号中的尺寸、错位测量地址及规则／AI 分类瑕疵地址：当前料号优先，其次保留已有独立配置，其他料号只补缺项；同一输出地址仅保留高优先级项目。停用项目保留停用状态，有效 AI 地址默认启用。

新配置成功保存后清空对应旧输出地址并记录迁移标识。旧的其他尺寸输出地址也清空，不再发送；迁移完成后在两个独立页签维护，不会再次用旧料号覆盖手动修改。尺寸保存为 AllSizeInteractionConfig.json，瑕疵保存为 DefectInteractionConfig.json。

非法单项保留必要旧地址，保存失败保留对应旧配置并在下次启动重试，旧发送链路不会恢复。启动提示异常摘要时，查看软件日志中的“PLC交互迁移”，核对未迁移项和冲突取舍。两个页签保存时统一检查名称、数据集、地址类型和重复地址；修正提示后再保存，停用项也不能与其他项目占用同一地址。

控制器读写与通信排查

在“系统设置 → 系统控制器”检查型号、IP 或串口，再检查各点位的读写方向。读写测试使用“地址|类型”，类型为 int、bool 或 float，并填写与类型一致的值。

手动写入会影响真实设备点位，测试前应确认设备状态和目标地址。系统控制器未启用时，参数下发和读写测试不可用。

MES 上传失败时，分别核对功能启用、网络连接、接口请求与返回。卷号获取、数据上传、登录或日志上报是不同业务，单个接口成功不能代表其他接口也成功。

连接正常但没有输出

检查顺序需要确认
1. 连接对象主设备 PLC、系统控制器、纠偏设备和 MES 是不同对象，检查实际输出使用的通道。
2. 触发条件报警是否达到计数条件，纠偏是否满足采样与许可，尺寸输出是否有匹配的有效数据。
3. 点位及格式核对地址、读写方向、float／int／bool，以及对应功能的缩放规则；不要将尺寸交互PLC的四舍五入与纠偏的截断混用。
4. 本次返回查看同一时刻的发送结果与错误，不以历史连接成功替代本次写入确认。
5. 接收与设备软件报告写入成功后，继续确认 PLC 中的值、设备许可和接收端处理。

以“尺寸交互PLC”为例，显示 12.345 时，float 输出保留测量数值，int 输出将值乘以 100 后四舍五入。接收端必须按同一比例解释。该示例不能套用到报警布尔信号或其他通信功能。

MES 上传失败保留哪些信息

  • 记录发生时间、接口用途、料号与卷号，区分卷号读取、生产数据上传和文件通知。
  • 保留本次返回码、返回正文及软件错误，不只记录“网络正常”。
  • 核对本地待处理文件是否生成；文件同步和 MES 业务确认属于不同环节。
  • 项目专用接口按该接口要求处理，不能以一个接口成功推断全部业务已完成。
