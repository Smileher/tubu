日志与诊断

使用软件“查看日志文件”打开日志根目录。日志在与 App 同级的 Logs 中，按日期和分类归档，例如 Logs/20261022/Error/。

分类主要内容
Info初始化、设备连接、启停和换卷等运行阶段。
Records用户操作、通知、生产报警及相关权限信息。
Debug检测、通信、相机启停和性能细节。
Error异常、超时、通信失败和需要关注的技术告警。

日志约 10 MB 后分卷。收集故障资料时直接复制当天整个日期目录，保留带 .1、.2 等序号的文件，同时记录软件版本、故障时间、料号、膜卷和操作过程。

“软件信息 → 导出诊断包”可生成诊断资料；“建议与反馈”可打开反馈入口。参数变更审计与 TXT 运行日志属于不同记录，查看参数历史时使用软件审计入口。

按阶段分析问题

启动慢时，在 Info 中搜索“启动步骤开始”“启动步骤完成”和“启动里程碑”，按模块比较开始、耗时与累计时间；并行模块的耗时不能直接相加。分别核对“后台初始化开始”“检测初始化就绪”“后台初始化结束”“主界面布局与首帧等待结束”和“主界面首次可见”。初始化期间只显示进度窗，首帧等待超过 2 秒会记录异常并继续交接。初始化就绪仍需通过原有权限、相机、标定、配置及模型校验。

进度摘要会移除已完成的模块，最多显示两个简短模块名和待完成数量，完整名称在步骤日志中查看。百分比按阶段推进，单个模块加载超过 3 秒且没有其他待完成项时显示该模块用时。看到等待 PLC 或相机时，先核对对应步骤的结束日志，不把等待时间归到前一个已经完成的模块。MES 分别记录配置读取、应用和连接耗时；未启用的喷码会记录跳过原因。设备普通连接失败和连接超时只显示红色状态，详细原因仍写入日志；读取、加载失败及程序异常才进入启动汇总提示。

初始化结束后仍需等待较长时间时，在 Info 中搜索“启动界面阶段”，分别查看主窗口控件创建、首次主题、首次同步布局、首次布局调度与控件加载、首帧信号等待等耗时。主题未变化时会记录跳过重复应用。界面日志用于定位交接耗时，不表示实际相机已出图。

启动步骤异常或超时在 Error 中记录模块、耗时和详细异常，设备日志同时包含相机、地址、SDK 阶段等信息。常规本地配置、数据库、缓存及单路 PLC、控制器初始化默认等待 10 秒，单台相机和单个 AI 模型默认等待 60 秒；已有更短驱动超时继续生效。MOM 取参沿用通信设置的超时预算，包含排队等待。超时表示本轮结果未被采用，不能据此认定原生 SDK 已停止执行。

  1. 先明确现象：没有图像、检测结果不对、文件没保存、点位没更新或设备没动作，要分开描述。
  2. 再定位最后完成的阶段：启停搜索 SystemOperation，自动取流搜索 CameraAutoCapture，换卷按同一“换卷#”关联阶段。
  3. 查看相邻错误：找到最后一个开始但未返回的阶段，结合相机、控制器和保存日志分析；界面提示不是唯一证据。
  4. 保留原始信息：保存当天日志、提示原文和相关数据，避免反复重启或覆盖文件导致线索丢失。

初步排查可以缩小问题范围，但连接成功、试检通过或文件存在，都不能单独证明整条现场业务链路正确。

查看参数变更记录

通过顶部“日志”菜单进入参数审计，按时间和相关条件查找变更。先核对变更对象、保存时间和修改内容，再和故障发生时间比较。

审计用于查看变更历史，不会自动恢复旧配置。运行日志用于判断执行阶段，二者应结合查看。输入框改过但未保存，与参数已经写入并生效需要区分。

启动时先初始化审计数据库，再处理料号与 PLC 地址迁移。出现“写入审计日志失败”时，核对数据库初始化结果，以及测量数据库目录下 SystemLogs/AuditLog.db 的目录、写入权限和磁盘状态；TXT 运行日志与审计库是独立记录。配置可能已经保存成功，不能仅凭审计失败认定迁移失败，也不要删除数据库或清空原配置。

导出诊断包

通过“帮助 → 软件信息”核对版本，点击“导出诊断包”，在选项窗口选择需要的资料和输出位置，再执行导出。按实际问题选择日志与配置等资料，保留故障时的原始文件。

解压后先查看根目录的“导出说明.txt”。文件名沿用原有时间命名，来源和环境信息记录在说明中：

信息用途
诊断设备标识、计算机名设备标识由有效硬件 UUID 生成，用于辅助核对是否来自同一工控机，与授权机器码无关。读取失败会记录原因，不使用固定兜底码。更换硬件或硬件标识异常时需结合计算机名、MAC 和工位核对。
现场、工位、设备编号及程序信息区分不同工位和软件目录；结合进程 ID、软件启动时间判断是否为同一次运行的前后导出。
本机网卡及通信配置查看系统返回的全部网卡，包括断开、虚拟和回环接口，以及 IP、掩码、网关、DNS、DHCP、MAC、接口类型和链路速度。保存配置摘要列出 PLC、控制器、相机、MES、工位交互和 FTP 等已有地址；网络端点只保留主机和端口，不展开账号、密码和请求参数。
运行状态与系统资源记录导出时的软件运行状态、料号、膜卷号和已有设备状态标志，以及 Windows、CPU、内存和本机固定磁盘容量。设备状态标志为 False 也可能是未启用或未初始化，不能单独判断为断线。

“已保存配置摘要”与“导出时运行状态”分开记录。勾选 Config 时，摘要读取成功收集的配置副本；未勾选时，仍从磁盘 Config 只读提取白名单摘要，不打包完整配置。缺少字段不推断默认值；保存值不代表当前连接实际采用的地址，需重启生效的参数尤其要核对。环境信息按各自时间采集，不还原故障时状态，也不主动测试设备连通性。

部分环境信息读取失败时会注明缺项并继续收集其他资料。摘要对网络端点的处理不改变完整 Config 和日志原文的收集规则。

提交问题时补充发生时间、当时操作、当前料号和膜卷号、涉及相机或设备，以及能否稳定重现。提示窗口应保留完整原文，不只记录“失败”。

软件打不开时导出诊断包

将独立工具 导出诊断包.exe 放到待诊断软件的 Bin 中即可运行，无需先打开主软件。工具按自身所在位置识别 App、Config 和与 App 同级的 Logs，也兼容原 UtilityTools 子目录部署；独立放置时可在高级设置中手动选择 App 或 Bin。图标已内嵌，使用时只需复制 EXE。

  1. 在“高级设置”核对“App目录”和“主程序”。Config 自动定位到 App 内的 Config，软件日志自动定位到与 App 同级的 Logs，不再单独指定日志目录。唯一已知主程序自动选中；发现多个候选时选择本次故障的软件。未识别主程序时仍可采集已保存资料，说明中会记录程序信息缺项。
  2. 填写必填现场信息：项目名称、项目编号、问题描述类型、故障时间、问题表现和临时处置。问题类型可选蓝屏、界面卡死、功能失效、异常 Bug 或其他，具体操作和现象填写在“问题表现”中。处置可多选，未处置时明确选择“未处置”，选择“其他”需补充文字；这些选项只记录操作，不执行重启。
  3. 故障时间选择“准确时间”或“估计时间”后，勾选并填写日期和时间；“刚刚发生”可填入当前本机时间。记不清时明确选择“时间不详”，导出说明保留这一标记，不替换成导出时间。
  4. 需要补充故障画面时，点击“添加截图”，可按 Ctrl 或 Shift 多选本地图片，也可分批添加。列表显示已选路径，选中后点击“移除选中”只移除本次附件，不删除原图。勾选“其他”处置后，在其右侧短输入框补充具体措施。
  5. 点击“高级设置”选择 Config、软件日志和系统日志（Windows Application、System），默认全部勾选，至少保留一类。“过滤 Config 内常见图片文件”默认开启，按扩展名过滤 BMP、JPEG、PNG、TIFF、GIF、WebP、SVG 等图片，大小写无关；需要原图时可关闭。图片过滤只作用于 Config，不按大小排除模型、数据库或标定文件，说明中记录过滤数量和原始大小。
  6. 在“高级设置”核对日志日期，默认包括今天及前六天，格式为 yyyy-MM-dd。支持日期目录、分类目录下的日期文件和带序号的分卷，无法识别日期的文件会注明跳过。日期筛选只影响日志和 Windows 事件；故障时间落在范围外时会提示，可返回调整或确认继续。
  7. 未找到与 App 同级的 Logs 时，弹窗可选择继续、打开高级设置调整 App 目录或返回；继续时导出其他可用资料，并在说明中记录日志缺项。
  8. 在“高级设置”核对保存位置，默认当前用户桌面，可点击“修改目录”选择 ZIP 文件位置。保存位置必须在 Config 和 Logs 之外，已有同名文件时确认覆盖。点击“导出”后等待完成或部分完成，默认打开所在目录。

解压后先查看“导出说明.txt”，开头为现场故障说明，后续记录路径、时间范围、图片过滤、截图附件、环境及缺项。问题截图放在 ZIP 的“问题截图”目录内，按选择顺序添加序号以区分同名文件；截图不受 Config 图片过滤影响。图片不存在、被独占或无法读取时记录缺项，继续收集其他可用资料。高级设置底部提供“关闭”按钮，点击后使用当前修改；点击标题栏关闭或按 Esc 也会保留修改，同次运行再次打开可继续调整；重新启动工具后恢复默认值，不保存到下次运行，也不写入主软件配置。截图列表也只在本次运行中保留。目录、日期和打包内容仍在导出前校验。

工具可与主程序同时运行，只收集磁盘上已保存的资料；数据库生成已提交数据的一致副本，文件被独占或无权限时记录缺项并继续。部分完成也会生成 ZIP，不能把它当作全部资料已收集。所有项目都未收集到文件时会提示失败。

外部工具无法取得主程序内存中的料号、膜卷号、设备业务状态，也不能刷新主程序尚未落盘的日志；主程序进程信息按实际读取结果记录。工具不采集崩溃转储（dump），不修改配置、不主动测试设备连接。除主动勾选的图片过滤外，Config 和日志保留原文，可能含现场账号、密码或令牌，发送前应核对接收对象。

Windows 事件或环境信息读取失败时，在结果和说明中记录原因。可点击“取消导出”；导出中关闭窗口会先取消并等待临时副本清理完成。若提示清理失败，保留提示中的路径供排查。

常见现象从哪里查

现象优先检查
没有图像相机连接、启用状态、触发方式、编码器信号和采集日志；参见相机与采集。
尺寸偏差或抓不到边原图、标定、区域、方向、极性、阈值与补偿；参见直线与尺寸。
瑕疵少检、误检或类别不对检测区域、模板、模型、面积过滤及二次分类；参见分类与过滤。
报警后 PLC 没动作触发条件、事件开关、连接、地址、类型与写入结果；参见报警设置。
纠偏没有输出设备连接、启用、有效样本、死区、输出限制及实际发送记录；参见闭环纠偏。
查不到数据或文件保存开关、筛选、数据库、路径、卷号、空间与清理记录；参见数据保存与查询。

通用说明不能替代项目专用协议或外部设备确认。先收集可以对应同一时刻和同一对象的证据，再判断问题在哪个阶段。

一次问题记录包含什么

  • 时间：精确到分钟或秒，注明第一次发生与最近一次发生。
  • 对象：软件版本、当前料号、膜卷、相机、面别和相关设备。
  • 操作：发生前做了什么；停止再启动、更换图像或切换料号后是否仍发生。
  • 原始资料：完整提示、故障当天日志、原始图像或对应结果文件；参数问题同时保留相关配置。
  • 已经确认的事实：例如有回调图但没有检测结果、写入返回失败、某卷报表缺失，分别记录。

用同一时间和同一对象关联资料。只说“没有反应”难以区分未触发、正在等待、已失败还是外部设备没有动作；可从通信检查顺序或开检提示进入。
